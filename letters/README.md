# letters/

A letter here is **a draft for one person**, and writing one is how this world
tells somebody something true about themselves.

**A file in this folder is a draft.** It shows up at `ofme.ai/letters` the
moment it lands on the default branch. Nothing is sent, nobody is contacted,
and no link exists until I make one.

**Write as many as the work needs.** There was a time when a second letter
replaced the first — that was a limit in our database, not a rule about
letters, and it is gone. Each file becomes its own letter at its own address,
and one of them appearing never disturbs another. Give each a distinct
filename; `letters/<YYYY-MM-DD>-<recipient>-<slug>.md` is the convention.

**A REVISION SAYS WHAT IT REVISES.** Rewriting a letter still means a new file
— the old one has been read at its path and editing it in place does nothing —
but a new file was also becoming a second line item on my letters page, next to
the one it was meant to replace. So say so in the front matter:

```
revises: letters/2026-08-04-anna-the-drive-home.md
```

Then the two are one letter with two versions: my page shows a single row
reading `V1 sent · V2`, and its link opens whichever version I actually sent —
because that is the one somebody else is holding.
Mark the earlier one `lifecycle_status: superseded` in the same commit: the
page groups by `revises`, but the map and the search index read the mark, and
without it the old draft keeps turning up beside the new one.

**Only when it really is the same letter.** Two letters to the same person
months apart about different things are two letters, and joining them hides one
behind the other. Leave `revises` off and you get the old behaviour, which is
the right behaviour most of the time. Nothing guesses this from the recipient;
it is knowable only by whoever wrote it.

## Why the file is the ingress

Restricted egress is the normal case for an agent, not the exception, and a
capability that only works from one machine is not a capability. So the world
is the ingress: any agent with write access to this repository can write a
letter using the access it already has — no endpoint, no key, no outbound
request.

## Before you write one: the brief

**A letter does not exist until I have told you what it is for.** Each one is
bespoke to the asking, and four things decide everything about it:

| | |
|---|---|
| **From** | not a choice, and not a field to guess at — yours, always. See the voice rule below |
| **To** | one named person. Not a list; a letter to everyone is a newsletter |
| **Goal** | what it is for. A letter with no reason to exist is the thing this prevents |
| **Tone / voice** | how it should sound, in my words |

If I say "draft a letter" and you do not have all four, **ask me before you
write a word.** Guessing produces a letter that reads like a letter and is
about nothing, and I will have to tell you the same four things anyway — after
reading something I did not want.

These are not a template. A letter to my grandmother about a summer and a
letter to a skeptical colleague who needs every claim cited are the same four
fields and nothing else in common.

## Writing something that passes between two people

A letter, a playlist, a page. One form — a playlist is a letter carrying a track
list, and everything above the list is the letter.

### Two readers, one of them addressed

Addressed to one person, read first by the other. I see it before they do; they
see it only if I pass it on.

- **Exactly one named person.** A letter to everyone is a newsletter.
- **I am not the author.** I am the source and the first reader.
- **I am the gate.** What I will not hand on reaches nobody, however good.
- **I am the editor.** I can change it before it goes.

### The voice is yours. Always

No branch, no per-recipient judgment, no field on the brief. Judgment is what
drifted last time.

**The test: if this is in my voice, why does it exist?** I can already write in my
own voice. The one thing I cannot do is hold the whole record at once and say
what it adds up to — and that sentence can only be spoken by whatever did the
holding.

**Write as what you are.** Never as a person from my life. That unlocks three
moves first person cannot make: **attribute instead of impersonate** (*he said X*
is evidence; *I say X* is words in my mouth); **say what I cannot say about
myself**; **name the shape I could not see**, because I lived it in sequence and
you read it whole.

**Distance does not soften it** — a letter to somebody close fails loudest.

**Say what you are in the first line or two, plainly.** *I'm a machine* does it;
*an account assembled from* does not. One clause. Never an apology.

**That is for the FIRST thing they ever get from you. After that, open as
somebody who has met them** — their name, and that it is you again. The
disclosure exists so
nobody is misled about what they are reading; once it has been made, making it
again is not extra honesty. It reads as amnesia performed as scrupulousness, and
it tells someone who spent an hour talking to you that you have no idea who they
are — which is the exact opposite of what this whole thing is for.

**Check before you open.** Other files in `letters/` name their `recipient:`,
which is the cheap first pass — but it is not the whole answer, because things
reach people by other roads: a piece written for them, a page passed on, an
evening they spent talking to you directly. Look for those too. **Absent
evidence either way, treat it as the first** — a needless introduction is
awkward, and a familiar opening to a stranger is worse.

**None of this licenses pretending to be a person.** Warmth on a second letter
is not a claim to be human, and if they ask what you are, or the letter turns on
it, say it plainly again in your own words. The rule is against reciting a
disclaimer, never against being honest.

**Ghostwriting on request is a different job and it is fine** — a work email, a
card inscription, drafted as me because I asked. **These are never that.**

**What I write is a declaration; what you write is evidence.** A promise from a
machine is worth nothing. An assertion about the record from me is just an
assertion. Neither does the other's job, so the strongest thing is both together.

### Ties go to the recipient

Which reading of an ambiguous line, who a comparison casts as which character,
whose effort a sentence credits — **absent instruction from me, all of it
resolves toward the person receiving it.**

I read the draft against what I meant, so an implication I never intended gets
filled in by my own memory. They have only the words.

**Never at my expense either.** An artifact generous to them and unflattering to
me does not get argued with; it gets closed, and nobody receives anything.

**Write it interlocked, not loose.** A paragraph nothing else touches is
decoration. Just keep the joints visible — never introduce a fact inside a
reference and lean on it later as though established.

### The connective tissue is the product

**Say the thing that requires holding all of it at once** — the arithmetic nobody
in the story can run, because they lived it in sequence. Two things said years
apart, in answer to different questions, that are the same thing.

**One finding followed all the way down beats nine touched.** Most material ends
up on the floor. If most of it made it in, it was summarized rather than read.

**The telling is input, not an outline.** Answering in the order asked produces a
better-dressed recording, which is the one outcome that makes it pointless.

**End where the finding ends**, not where the material runs out.

### Reaching outside the record

One reference from the world outside my life per finding, at most.

**Three jobs, all three:** it **zooms out** and comes back down (a shot that stays
wide is a lecture); it **bridges the personal to the permanent** — *you are not
peculiar, you are human, here is the mechanism*; and it **teaches** something
true. Which corrects *analogy, never information*: teach on the way through, but
never let the sentence *end* on the fact about the world.

**Turn it, do not deploy it.** A reference you argue with has done work; one you
state has decorated. Make the comparison, then say where it stops — **the place it
breaks is usually the sentence worth keeping.**

**Check the casting.** Name every role the comparison creates and say which reader
stands in each. If the recipient is the deficit, the antagonist, the patient, or
the party a shortfall is charged to, it is wrong however perfect the fact. If I
am the failure, it is wrong too and will never be sent.

**A re-aim means cut it, not aim again.** From the inside every reference looks
apt. So the test is not *is this good* but **does the finding need it** — cut it,
reread the page, and see.

**Checkably true.** **The gate is the finding, never the artifact.** **Illuminate
my situation; never describe my own domain back to me.** **It cannot rescue a
weak observation.** **Default off.**

### Always

**Quote exactly**, checked by hand — I will read every quotation knowing what I
said.

**Name your epistemics in the artifact**: this is one person's account, not a fact
about them. Not a disclaimer — it is what makes the rest trustworthy, and what
makes it safe for me to pass on when a line is close but not quite right.

**No ask.** No invitation, no obligation, nothing to answer, nothing added — no
prompt to share, no argument for how good it is. A page that requests something
has converted a gift into a chore.

**Never reproduce a lyric.** Name the song and say why it belongs. This fails
destructively: the artifact simply never arrives and nobody is told why.

**Proportion** — never longer to read than the telling took to say, measured in
words actually spoken. This governs the prose, not a track list.

### When it carries a track list

**The prose above the list is an overture, not a letter.** A letter has the whole
document to develop one finding; a playlist gives the prose a fifth of that,
because the tracks need the room. Asking the opening to be a letter produces a
short letter, which is worse than a good overture — measured, where the prose
read competent and flat while the three sharpest sentences in the artifact were
all track reasons. So the opening does three things and stops: **say what you
are, name the finding once with real force, and say whose taste this is.** Then
get out of the way. Its job is to make somebody trust the list, not to be the
thing they keep.

**Never spend the same moment twice.** If a track's reason is going to carry the
couch, the two hands, the thing that got said — then the prose gestures at it and
moves on. The same run put one image in the opening and again under track twelve,
and each appearance halved the other. **Material spent above the list is spent**,
and the reasons are where the best writing should be: by track seven somebody has
stopped reading an introduction and started being handed things, which is where a
sentence lands hardest and a flat one costs most.

**Anything to work from means 10–15 tracks as a floor.** Two things are shown and
the prose carries one: the narrative work, and **the musical work — opening one or
two named artists into the surrounding sphere.** A short list never shows the
second.

**Expand in several directions** or it is a subgenre playlist: deeper into the
same artist past the hit; sideways into the same scene, years, label; **backwards
into what that artist was plainly listening to**, where the surprises are;
forwards to whoever took it further; through the room — the producer or the
players behind a sound somebody loves and has never thought about; the original
behind a cover.

**What the anchors buy is the universe, not the answer.** They define a
neighbourhood a few degrees out — Kevin Bacon distance, deliberately generous —
and that is where the search runs. A wide space is safe here *because* meaning
does the choosing; breadth is only dangerous when adjacency picks, since then the
edge of the space becomes the answer. So the anchor is not a fence. What it buys
is **provenance**: a traceable path from what I named to what I was handed, which
is the first half of a good reason.

**At most a third of the list may come from the artists named.** A cap, not a
target, and it exists because the alternative was measured: given three artists,
one run returned twelve of fifteen tracks from inside them. **"Yours" is not a
reason** — an anchor track earns its place on exactly the same bar as any other,
and it is easier to justify a track they already own, which is precisely why it
cannot be allowed to be cheaper. An artist's own band counts as that artist: if
the listener would say *that is basically the same artist*, it counts against the
third.

**Substance is the only selector, and it is the win condition.** A song earns its
place because what it is *about* meets something the record establishes in my own
words — never inferred. Same operation as the connective tissue, run against a
wider index: one index is my life, the other is everything ever recorded. A list
that gets substance right using famous tracks has succeeded.

**The track is a commodity. The reason is the product.** A streaming service can
put the same song on a list and will sometimes pick a better one. It cannot say
why this song is here for this person. So *it fits the mood* is a streaming
service's output reproduced worse — cut the track.

**Lesser-known is a bonus, never a requirement.** Popularity says nothing about
which track is right for one person, and neither does whether I already own it.
A song in my library or on one of my own lists is not disqualified — if it fits,
it fits. What stays true is the line above: being mine is not the reason; the
reason is.

**The mission, so the rules above are read in its light.** Play somebody good
music that is poignant to the relationship, and make the reason known. *Good* is
subjective, which is why the reason carries the weight the track cannot — the
song is the commodity, the reason is the product. Nothing here asks for an
esoteric cut. An esoteric cut is a bonus when it is genuinely the better answer,
and a failure the moment it is chosen for being rare. **A track that plays, with
a reason only this house could have written, is the whole job.** A track that
does not play has not done any of it, however perfect the pick.

**Match on what the song says, not on what it is famous for.** These feel
identical from the inside and are not. *This is the plainest song ever written
about that* is a claim about a song's reputation, and reputation is exactly what
made it famous — so reasoning that way returns the hit every time and calls it
substance. The operation is to read the lyric against something in my own words.
A note you could have written without knowing how the song actually goes has
picked a title, not a track.

**A half-remembered clue is a lead to run, not trivia to file.** *"That guy who
opened for him"*, *"the one that goes something about a river"*, *"a song that's
like Dostoyevsky"* — when I hand over a detail I cannot resolve, that is a
searchable fact about a real record, and going and finding it is the single
highest-value thing available. Filing it under open questions is not caution; it
is the work, declined. Caution is about the *answer* — cite what you found, say
how confident it is, and never write a plausible name as a settled one.
**Twenty years of not knowing can end in one search, and it will be remembered
long after the track list is.**

**And the right track is not in the tail either.** There is no depth in a
catalogue where the good one lives — the hits are simply the ones that got the
push. Do not sample the tail and do not sample the top.

**Sequence it rather than ordering it.** At album length this stops being a
running order and becomes a shape: anchors at the load-bearing positions — the
opener, and wherever the list needs to re-establish that it knows me — with the
furthest reaches in the middle, where somebody who trusted the first three tracks
will follow. **Never run unfamiliar songs consecutively**; four in a row reads as
a lecture however good each one is.

**A song titled for a word out of the telling is a lead, never a pick.** A title
match on its own is a parlour trick and it will be sniffed out: if matching the
word is the mechanism, the object stops being about them and becomes a
demonstration. What earns the place is the *meaning of the words* meeting
something that was said — so read the song before using it, and drop it if it
points the other way however good the coincidence looked. When it does fit, it is
the best thing a list can do.

**Do not flinch from hard subject matter.** A song about death is not disqualified
by somebody having lost people; a song about addiction is not disqualified by
somebody being in recovery. Those are the songs that land hardest, and steering
around them is a condescension dressed as care. **The weight rule governs what
your sentence claims, never what the song is about** — the failure is a reason
that narrates somebody's grief back to them, or that rests on something inferred
rather than something said.

**Never invent a track.** Verify title and artist. A fabricated song breaks the
exact promise being made: they go to play the thing found for them and it is not
there.

## The shape

```markdown
---
record_id: ltr-<eight hex>       # required — the same numbering every record uses
conversation_id: conv-<eight hex> # only if it came out of one — see below
in_reply_to: <record_id>         # what this letter came out of — see below
in_reply_to_source: declared     # declared (I said so) or inferred (you worked it out)
recipient: <their first name>    # required — who it is addressed to
subject: <my name>               # required — who the letter is from
title: "<a title>"               # required
standfirst: "One line under the title."
created_at: <YYYY-MM-DDTHH:MM:SSZ>
illustration_object: <one object, or "" — required, and usually "">
illustration_surface: <optional, placement only — see the illustration section>
slug_lines:
  - label: Written
    value: <e.g. 4 March 2027>
memories:                        # each becomes a contribute button
  - title: <the memory, in a few words>
    teaser: <one line — what puts them back there>
    meta: <when it happened>
    record_ref: <path to the record it came from>
    record_title: <that record's title>
    topic: <what they would be adding to>
---

<Their first name> —

The body starts here. Paragraphs are separated by blank lines.

## A heading

> *"A quotation."*

-- How it is signed.
```

Body grammar is deliberately small: `## heading`,
`> quote`, `-- signoff`, `**bold**`, `*italic*`, and `==mark==` once per letter.
**No links and no images IN THE BODY** — no markdown image, no HTML tag, no
data URL, no picture pasted into the prose. A letter travels to people who did
not ask for it and should not be able to point them anywhere.

**That is not a rule against the letter having a picture.** A letter may carry
one drawn object, named on one line of front matter and placed by the page
itself, after the signature — see the illustration section below. What the body
may never do is carry an image of its own.

**Wrap your lines however you like.** A paragraph is whatever sits between two
blank lines, and the wrapping inside it is a detail of the file, not of the
letter — it is rejoined when the page reads it. **A blank line starts a new
paragraph. Two spaces at the end of a line force a break** where you actually
want one, like an address or a line of verse. You do not have to write a
paragraph as one enormous line to make it render as one, and you never had to.

**`conversation_id` WHERE THE LETTER CAME OUT OF A CONVERSATION**, and left off
where it did not. Most letters have none: I asked for one, you wrote it, and it
belongs to nothing but itself.

But a letter written at the end of an evening — a game at the table, a memory
somebody else filled in — belongs to that conversation, and so do the Afterword
and the records that came out of the same hour. **One id on all of them is the
only reason any one of them can be found from any other.** Without it they are
what the table was built to stop being: an Afterword here and a letter there,
about the same night, with nothing joining them.

The id is the one in `table/` — the conversation's own record. Copy it exactly;
never mint a new one, because a second id is a second conversation that nobody
was at.

**`in_reply_to` SAYS WHAT THIS LETTER CAME OUT OF, and `in_reply_to_source`
says how you know.** They travel together and neither is any use alone.

```
in_reply_to: conv-8a1c9911
in_reply_to_source: declared
```

Two values and they mean different things:

- **`declared`** — I asked for the letter from that record, or I told you
  which one it was about. That is an act, not a reading, and nothing automatic
  ever overwrites it.
- **`inferred`** — nobody told you, so you worked it out from what you read
  while writing. A pointer, exactly like every other inference in my home: it
  may say where to look and it may never be cited as evidence.

**When nothing told you, look before you write, not after.** You are already
reading my home for the letter's material; keeping the id of whatever it turned
out to be downstream of is a line of front matter written while the file is
open. Working it out afterwards costs a whole second pass over everything.

**And leave both off rather than guessing.** A wrong anchor puts a letter into a
thread it does not belong to, where everything downstream reads it as context. A
letter with no `in_reply_to` is merely unthreaded, which is visible and can be
fixed in a second. A wrongly threaded one is invisible and gets believed.

**If the record you anchored to carries a `conversation_id`, copy that across
too.** The two fields answer different questions — *what is this a reply to* and
*which conversation is it part of* — and a letter three replies deep into an
evening needs both to be found from either end.

### Writing back to somebody? Read `sources/received/` first

When another member deliberately shares something with me and I open it signed
in, a copy lands in `sources/received/` carrying the author, the day, and the
`record_id` and `conversation_id` it was written under. **That is the parent
of anything I write back**, and it is already in my home — so a reply never has
to ask me what it is replying to, and never has to guess.

It is their material and it stays theirs: `contributor_handling: testimony`.
Draw on it, attribute it, and never fold it into my records as though I had said
it.

**The id is not decoration.** `record_id: ltr-<eight hex>`, minted the same way
as every other record in my home — see [the write contract](../records.md). It is
what lets a letter be pointed at from another record, handed to one named person,
and carry an illustration. Letters went without one for a long time and the cost
was invisible: everything keyed on ids simply skipped them.

**`created_at` carries the time, not just the day.** Stamp the full moment you
wrote it — `2026-08-21T22:04:00Z` — not a bare date. It costs nothing at write
time and it is the only thing that can tell two letters written on the same day
apart; see [the record contract](../records.md) for why.

## An illustration, if the letter holds one object — the picture is optional, the line is not

A letter may carry **one drawn object**, in the same house style as every other
picture here. Most letters carry none, and that is the ordinary outcome: **no
suitable object means no illustration**, and the page then shows nothing at all
— no placeholder, no caption, no empty frame where one would have gone.

**But every letter carries the `illustration_object` line**, holding
the object or `""` when there is none. The page cannot tell an empty value
from a missing key; the next reader can, and the difference is whether anybody
looked.

**The prose carries the letter. The illustration carries one object from it.**

### What may be drawn

Choose one visually strong, concrete object genuinely grounded in the telling. It does not need to symbolize or summarize the memory. Its job is to evoke, not explain. Prefer the object that could only have come from THIS telling over the one that could have come from any of them.

**Grounded in what this letter was allowed to use.** The object comes from the
material already cleared for this letter — the memories it was built from, the
records it cites. Never from something the recipient's own §Handling keeps
inside my house, and never invented.

**Prefer an object that CANNOT be drawn wrong. Ask: does the person remember this thing specifically? A car, a house, a room, a particular stretch of landscape are all things they can picture exactly, so any version you draw will contradict the one in their head and then sit in their record for years. So: either be right on point with precision, or choose something with less variation. Precise means the source NAMED it — draw the two-door Ford Explorer only if they said two-door Ford Explorer. Otherwise take the thing whose APPEARANCE nobody remembers exactly: bubbles rising through water rather than the creek, the scissors rather than the salon, a speedometer sitting at zero rather than the car around it. AND LOW VARIATION IS ABOUT HOW IT LOOKS, NEVER ABOUT WHAT IT MEANS. A compact disc is safe to draw and could belong to anybody's answer about a song; a speedometer at zero is just as safe to draw and could only be this telling — and it says *parked* without drawing the car. When two objects are both impossible to get wrong, take the one that could only have come from this telling.**

**It must be recognizable as what it is, drawn alone, with no label and nothing beside it to explain it. If somebody would have to be told what they are looking at, choose something else. An accurate drawing of an unrecognizable thing is worse than no drawing.**

**See what has already been drawn, before you choose.** **A tool called
`drawn` answers this in one call if you have it** — no arguments, every object
this house has already used. With a shell instead:

```bash
grep -h "^illustration_object:" letters/*.md afterwords/*.md | sort
```

With neither, say so and choose an object the letter makes specific to itself.
Search cannot stand in — it skips front matter, and this line lives nowhere else.

Do not choose an object already drawn for another record in this house. Two of the same object in one house reads as a broken feature
rather than as two pieces of writing.

ONE OBJECT ONLY. Do not add supporting props, contextual objects, people, labels, signage, or narrative clues. Never a reconstruction of the event, never people, never a
symbol the material does not mention.

LETTERING THAT IS PART OF THE OBJECT STAYS. A sign, a spine, a dial, a moulded label: those words are the shape of the thing, and drawing it without them draws a different thing. What is never allowed is lettering ADDED — a caption, a title, a slogan, a date, or any of the prose this picture sits beside. Draw the words that are on the object; never write words about it.

### Where you write it — the front matter, never the prose

```yaml
illustration_object: a weathered dock piling
illustration_surface: isolated, with nothing around it   # optional, placement only
```

**Those two lines are the whole of what you write.** The prompt is rebuilt from
them at drawing time, in whatever the house style is by then, so nothing goes
stale and there is nothing else to store. A third field explaining the picture
is read by nothing — a long note about colour, reference photographs or what to
avoid is invisible to the renderer, however carefully it is written.

`illustration_surface` is about PLACEMENT, never about place:
*"resting on a plain surface"*, never *"on the boards at the pier"*. If it
starts to identify anywhere, it has become the second half of a scene.

**"No links and no images" still holds, and it is about the BODY.** No markdown
image, no HTML tag, no data URL, no picture pasted into the prose — a letter
travels to somebody who did not ask for it and must not be able to point them
anywhere. The plate is not that: it is one file the page draws itself, from the
line above.

### Where it appears — the page places it, and you do not

**The application decides where the picture sits**, and it puts it in one place:
**immediately after the signature**, and above the dates, the memories it was
built from and the fine print. A letter with no signoff gets it at the end of
the body.

So there is **nothing to write to place it**. No heading over it, no caption, no
markdown image, no sentence saying a picture follows. Anything like that in the
body is a second copy of something the page is already drawing — and a drawn
page of stationery, a postcard, or a picture OF the letter is not an
illustration of one.

### What actually makes the picture

**Writing the line into a NEW letter file is the request.** The letter is drawn
once, at the moment that file is first read into my letters — automatically,
whether the letter was written by Of Me or by an AI writing the file straight
into my home. Opening the letter again, or refreshing it, never draws anything
and never costs anything.

**On a letter that has already been read into my letters, the line alone does
nothing** — the file is read once, at its path (see the rules below), so a field
added to it afterwards is not seen. Write the revision as a new file with its
own `record_id`, which is what a revision is here anyway.

**If a tool called `draw` is on your list**, that is the way to ask for one
directly: one call, the letter's `record_id`, and `redraw: true` only when a
picture is already there and the object has genuinely changed. If you can make
images yourself, file yours at the path below instead and nothing is spent.

**If you can do neither, the line in the front matter is a complete answer** and
you have finished. Do not apologise, do not say a picture is coming, and do not
describe the picture to me in words instead.

### One object. No reconstruction.

Never make:

- a collage
- multiple thematic props
- a staged tableau
- several story clues arranged together
- people recreating the event
- invented faces
- an AI reconstruction of what happened
- symbolic objects that were not in the source
- text or signage added to explain the memory
- clutter of any kind
- cute or children's-book art
- a logo or an icon
- photorealism
- Victorian-gothic excess
- overly detailed work
- whimsy
- clip art
- cartoon styling
- glossy digital rendering
- dramatic perspective
- a decorative border

### Background

Background scenery only where generic and subordinate: a plain surface, texture, a shadow, negative space, restrained atmosphere. It may not introduce a second meaningful object, identify a place, explain why the object matters, or stage evidence for the viewer.

### The style — the same one everything else here is drawn in

- illustrated like a small editorial engraving from a beautifully typeset literary book
- sparse black-ink linework
- subtle woodcut/etching texture
- imperfect hand-drawn edges
- restrained detail, lots of negative space
- familiar, well-used and quiet; evocative rather than technical

Straight-on elevation, centered composition, isolated on a transparent background where supported and a plain neutral ground where it is not. Monochrome, or an extremely restrained two-tone palette.

**Same visual language as an antique typewriter, an open book, a wooden drawer, a long kitchen table, and a simple old American house rendered as sparse editorial engravings.**

### Where it goes

```
illustrations/<record_id>.png
```

One folder for every illustration in my house, and the letter's own
`record_id` is the filename — which is why a letter without one can never
carry a picture. It lives in my **media store**, never in the repository: bytes
committed to git are in every future clone forever. Removing one is deleting
that file, and the place it used to be simply closes up.

## Rules that are not stylistic

- **A letter is a disclosure about somebody.** Everything in
  `people/<them>.md` §Handling governs it. A minted letter has a URL, and a URL
  travels — so anything marked internal-only does not go in one, however true.
- **Quote them exactly.** Check every quotation against the record it came from,
  by hand if necessary. A letter is the worst place to paraphrase somebody.
- **Draft, never send.** I make the link and I send it. Of Me does not contact
  anybody and neither do you.
- **Newest dated filename wins** when more than one draft exists:
  `letters/<YYYY-MM-DD>-<slug>.md`.
- **A file is read once, at its path.** The first time the page sees a letter
  file it becomes the letter, and after that the file is only how it arrived.
  **Editing a letter file that has already been read changes nothing on the
  page** — it keeps serving what it read the first time, and your commit will
  look like it worked. To revise one, **give it a new filename** — a slug that
  extends the old one reads as the revision — or edit it inline on the page.
  The new file becomes the working copy and the draft it replaces is retired;
  a letter somebody already has a link to is never disturbed.
